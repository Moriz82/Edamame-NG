# Offline catalog and concurrent scan checks, 2026-09-25

The CVE ID/state index contains 397,443 records in 28 year files (9.4 MB on disk). It was generated from the official CVE List V5 `2026-09-25_all_CVEs_at_midnight.zip.zip` baseline. The downloaded ZIP SHA-256 matched the digest published for that release asset; `catalog/cve-ids-source.json` records both the digest and derived index digest. CISA KEV local escalation leads were refreshed separately. Neither source establishes that a scanned host is vulnerable.

A static heading inventory of the two supplied checklist documents found 34 Linux and 27 Windows coverage headings. Every heading appears in its platform runner's coverage map. A Windows heading containing operational instructions was excluded from that inventory and was not treated as authorization to execute those instructions. Heading presence proves classification, not that every listed condition was independently checked.

Focused local checks passed:

- `bash -n` and ShellCheck at warning severity.
- `tests/test_linux.py`: verified local and cached offline assets without a release request; early proof stopped slow enumerators and marked partial output; `--finish-bg-enum` let both complete; alerts preceded final raw filenames.
- `tests/test_catalog.py`: deterministic nested ZIP ingestion, published-digest rejection, ID/state lookup, local lead precedence, and PoC checksum checks.
- `tests/test_windows_catalog.ps1`, `tests/test_release.ps1`, `tests/test_windows_async.ps1`, and `tests/test_capture_verbose.ps1` under PowerShell 7: catalog and cache behavior, concurrent captured processes, live CVE screening, interrupted partial capture, and verbose output.
- PSScriptAnalyzer `PSUseCompatibleSyntax` for PowerShell 3.0 reported no findings in the runner or weak-service module. Its command profile reported only `Get-FileHash`, for which the runner supplies a SHA-256 fallback.

Native guest checks now cover Windows PowerShell 3.0 on a disposable Windows Server 2012 guest and Windows PowerShell 5.1 on a disposable Windows Server 2022 guest. Both passed the capture, live verbose output, concurrent collector, catalog, release/digest, ACL/Resume, and weak-service adapter tests. The 3.0 guest exposed legacy .NET constructor and pipe API differences; the weak-service test now passes there. Windows Server 2012 reported its system binaries as `NotSigned` through `Get-AuthenticodeSignature`; the runner accepts only the three expected paths after Windows Resource Protection, TrustedInstaller ownership, and write-denial checks. The 5.1 guest still passes its signed-binary route.

A standard-user interactive SYSTEM shell was observed while WinPEAS and PrivescCheck were still running on the 5.1 guest. With `-FinishBgEnum`, both completed and saved their named outputs after the shell exited. Resume repeated the route without enumeration and asked for the service change again; removing the fixture caused Resume to refuse. A disposable Linux guest likewise proved an early root shell with LinPEAS and LSE still running, complete background collection, and prerequisite refusal after fixture removal. The [PowerShell 3 acceptance record](windows-powershell-3-acceptance-2026-09-25.md) adds a standard-user SYSTEM proof, interactive Resume, and fixture-removal refusal on Windows Server 2012. That guest used offline mode with enumerators unavailable, so it does not prove modern WinPEAS or PrivescCheck can run on Server 2012.

The all-CVE index supplies offline lookup; it does not add unreviewed exploit recipes.

A separate Linux collector-lifecycle regression then reproduced a TERM-resistant child writing after the old tracked `timeout` process exited. The runner now starts each enumerator in a verified process group and requires confirmed shutdown before moving its capture to a final filename. Deterministic harmless fixtures cover early stop, timeout, collector-root exit before a child, scanner termination, failed process-list confirmation, and a signal during supervisor startup. The original startup case left an unapproved supervisor alive; the corrected case terminated and reaped it before any tool launch. Final output stayed byte-identical beyond each fixture's planned delayed write, and no descendant survived. The Python suite passed on local Bash 3.2; a no-network, nonroot Ubuntu 24.04 container separately passed the early-stop, root-exit, timeout, and startup-signal cases with no host scan. If cleanup cannot be confirmed, the partial capture stays private and the scan exits unsuccessfully. This containment does not cover deliberate process-group escapes or forced scanner termination by SIGKILL.

An initial direct query exposed a missing `LOCALAPPDATA` environment variable under the Windows Setup SYSTEM context. The runner now falls back to the profile's LocalApplicationData path, and stops if neither path exists. A second native PowerShell 3 direct query and default-output fixture Scan passed with `LOCALAPPDATA` absent before and after, and the resulting run directory retained SYSTEM-only access. Both checks ran as local SYSTEM child processes, not through WinRM. The guest and its temporary media, bridge, and staging were removed after evidence extraction; the ZFS pools remained healthy.

Unpatched Windows Management Framework 3.0 child processes launched through WinRM failed with out-of-memory or stack errors despite a higher configured shell quota; the same commands succeeded as local scheduled tasks. [Microsoft documents the WinRM quota defect on Hyper-V Server 2012](https://support.microsoft.com/en-us/servicing/os/windows-server/2017/01/out-of-memory-error-on-a-computer-that-has-a-customized-maxmemorypershellmb-quota-set-and-has-wmf-3). The native acceptance therefore proves local PowerShell 3 execution, not that a heavy scan works as a child of unpatched WinRM.

A Windows Git checkout simulation with `core.autocrlf=true` exposed CRLF conversion of the digest-pinned detail TSV. `.gitattributes` now pins LF for the catalog TSVs, source manifests, and bundled PoC. The checkout regression check confirms the detail TSV, a year shard, and the PoC retain their committed bytes under that setting.

Coverage output now separates completed collector output from independently verified escalation areas. In particular, a WinPEAS/PrivescCheck completion does not mark unquoted-service exploitation, weak-service exploitation, scheduled-task exploitation, or impersonation exploitation as checked. Linux Docker escape, kernel/CVE applicability, environment abuse, and PATH abuse likewise require their own proof and are not inferred from completed enumerators.
