Live DC testing found that SharpHound prefixes `--ZipFileName sharphound.zip` with a timestamp. The first scans collected ZIPs but Edamame-NG left them in `.capture`. The script now selects the generated `*sharphound.zip` and saves it after the alerts; both DC reruns produced valid final ZIPs.

A local standard-user account was created on disposable VM 1323 for a low-token test. `Start-Process -Credential` returned Access Denied. A direct token launch failed process initialization, and a scheduled task stayed Ready without running. The account and its protected test credential were confined to the disposable clone. No standard-user Windows scan or standard-user-to-SYSTEM proof is claimed. The member-host SharpHound limitation was observed under SYSTEM; [SharpHound's guidance](https://github.com/SpecterOps/SharpHound) requires a domain-user context for collection.

## Cleanup and remaining limits

All eight disposable VMs and the Debian container were stopped and destroyed after testing. Verification found no matching guest configurations or ZFS volumes. The three temporary bridges, two bridge-local HTTP servers, and staging directory were removed. non-test guests and other test guests remained running; source guests remained stopped. `labpool` reported healthy. No reviewed CVE exploit recipe or automated credential validation is present. Partial enumerator output was retained and labeled only inside the disposable guests, then deleted with them; CVE names are suggestions, not proof.
